# 个人博客笔记生成规范
## 文档概述
核心目标：生成结构紧凑、内容精炼、可读性强的个人博客笔记，包含介绍、核心原理、架构图等关键要素，避免冗余和大量空白。
适用场景：计算机领域个人博客笔记创作，涵盖编程语言、框架应用、系统架构、工具使用等技术主题。
前置依赖：了解 Markdown 语法、熟悉至少1个计算机技术领域。

## 内容质量标准
1. **精炼性**：
   - 句子简洁，单句不超过80字，不少于 40 字
   - 每段聚焦1个核心信息，剔除冗余表述
   - 避免过度拆分内容，能用一句话说清的不分成多句
   - 减少不必要的层级和空白，保持文档紧凑

2. **准确性**：
   - 技术原理引用权威定义，搭配简单案例说明
   - 代码/命令标注语言类型/操作系统，关键行添加注释
   - 禁用模糊表述（如"大概""可能"），数值精确到具体范围

3. **可视化**：
   - 根据主题选择合适图表类型（架构图、流程图、时序图等）
   - 每个文档至少包含1张Mermaid图，复杂主题可增加
   - 图表清晰、布局紧凑，与内容紧密关联

## 标准化结构模板
# 文档标题（格式：[技术关键词]+[核心动作]+[目标效果]）
## 一、概述
- **核心目标**：明确文档解决的技术问题，包含"输入→处理→输出"逻辑
- **适用场景**：简要说明适用的用户类型和业务场景
- **前置依赖**：列出必备的技术基础和工具环境（简洁列出，无需详细安装步骤）

## 二、核心原理
- **技术背景**：100字内说明技术产生的原因或核心痛点
- **核心逻辑**：拆解为2-3个要点，每个要点≤80字
- **类比说明**：用日常生活或已知技术类比解释
- **架构/流程图**：
  ```mermaid
  %% 图标题：XXX
  flowchart TD
      A[节点1] --> B[节点2]
      B --> C[节点3]
  ```

## 三、实操步骤（可选，根据主题调整）
- 按逻辑顺序呈现，每个步骤仅包含1个独立操作
- 使用"动作+对象+目标"格式描述，如"编辑配置文件，添加端口映射规则"
- 关键操作可补充"为什么这么做"，但需简洁
- 代码/命令块标注语言类型，关键逻辑添加注释，复杂代码拆分展示

## 四、验证与测试（可选）
- 提供2-3种可量化的验证方法，包含"操作命令+预期结果"
- 关键测试用例简洁呈现，避免冗余表格

## 五、常见问题与解决方案（可选）
- 简洁列出典型问题、原因和解决方案，避免过度展开

## 六、扩展推荐（可选）
- 列出2-3个相关技术文档链接或进阶学习方向

## 禁止行为
- 禁止口语化、情绪化表述（如"超简单""绝了"）
- 禁止使用模糊的版本描述（如"最新版""高版本"）
- 禁止暴露敏感信息（如真实API密钥、数据库密码）
- 禁止过度拆分内容，避免不必要的层级和空白
- 禁止冗余表述，能用一句话说清的不分成多句

## Mermaid图表规范
- 使用 ```mermaid 标记代码块
- 缩进使用2个空格，保持结构清晰
- 节点名称使用清晰的中文或英文，避免缩写
- 每个图表必须包含标题（使用`%% 图标题：XXX`注释）
- 避免图表过于复杂，单个图表节点数量控制在15个以内
- 图表紧跟对应文字描述，减少空白

## 协作逻辑
1. 接收需求后，确认技术主题、核心目标和版本要求
2. 严格遵循上述规范生成文档，优先保证内容精炼和可读性
3. 文档结尾自动添加"本文可直接转载分享，转载请注明来源"的声明
